MOD: Smart AI
ID:   smart_ai
STATUS: active code, ACTIVE (listed in scripts/active_mods.txt).

OWNERSHIP (2026-09-21 fix): units and buildings are matched to an AI
house by House identity (owner == aiHouse), never by GetName() string
(GetName returns the shared country/type ID, so same-country houses
collide). aiHouses excludes human, player-allied, and neutral houses
(Neutral/Special/Civilian via util.is_neutral_house).

What it does (scripts/mods/smart_ai/main.lua, ~230 lines; mod.json:
"Dynamic base flank defense and threat response"):

  1. FLANK-BREACH RALLY (every 30 frames): for each AI house (identity-
     matched, see OWNERSHIP above), if one of its buildings is below 85%
     HP, idle reserve combat units far from the breach (> 6 cells) get
     MoveTo + Hunt toward it. No per-unit change detection — while a
     breach persists the orders re-issue every scan.
  2. CAPTURE-AWARE VALUABLES GUARD (MVP): high-value own units (APOC,
      HTNK) that are idle, lone (> 4 cells from own centroid) and within
      9 cells of an observable mind-control threat (MIND live-observed;
      YURIPR/YURI rules/wiki IDs) get one MoveTo toward the own group
      (transition-only + 600-frame refresh; engaged units never yanked).
      Owner flips are logged as observations only and drive no decisions.
  3. COMMANDER (base) + OFFICER (units) — classic split, same
      30-frame scan, no extra World calls; ID-ordered, no RNG/clock.
      Commander: breach rally (item 1) + garrison directives below.
      Officer: capture guard (item 2) + escort + flip observation below.
      ESCORT OFFICER: each own V3 ([V3] INI-confirmed) gets up to 2
      nearest idle combat bodyguards (harvesters/MCVs/other V3 excluded;
      engaged never yanked) with destination memory + 300-frame refresh.
      GARRISON OFFICER (EXPERIMENTAL): idle own infantry within 12 cells
      of own BUNKER/NAPILL/GAPILL are ordered onto the building cell
      (vanilla enter-if-garrisonable, screen otherwise; BUNKER id
      UNCONFIRMED live — directive log prints the acted type for census).
  4. COORDINATION (mutual help, shared blackboard): Officer assigns
      first, Commander acts around it — rally skips escort bodyguards
      and threatened pullbacks (no order fights); breach position is
      published to cmdState and Escort stands down inside an active
      breach sector (15 cells / 120-frame memory), releasing guards to
      the rally with one log line. Order per scan: recon → Officer →
      Commander. One-scan lag by construction (hysteresis, no thrash).
  5. RESTART GUARD: frame-backwards detection resets scan, guard,
      officer AND blackboard state, so a new match starts clean.

KNOWN SUSPECT (static observation, needs a live log): rally issues
MoveTo + Hunt back-to-back — the Hunt mission may void the MoveTo, so
reserves might hunt from place instead of rallying to the breach.
Confirm with coordinates before relying on rally positioning.

What it does NOT do (older versions of this file described squads,
officers, escorts, a CapabilityRegistry and framework Timer/Query/EventBus
wiring — none of that exists in main.lua; no ForceGroup, no SQUAD_NUM,
no SetSpeedPercent escort):
  - no squads, no officers/commanders, no escorts;
  - no production, spawning, or credit writes (source-verified zero
    SpawnUnit/QueueUnit/AddCredits);
  - no capture/mind-control implementation (vanilla mechanics untouched).

HOW TO ENABLE:
  1. Add smart_ai to scripts/active_mods.txt.
  2. Start a skirmish vs the AI.

WHAT HAPPENS:
  - [AI Commander - <house>] flank-breach alerts when reserves rally.
  - [AI Commander] ownership-change observations on flips.
  - Capture-risk pullback lines when a lone valuable is threatened.
